# r3 外包装经验总结（legacy 参考）

> 旧 r3 是“Python 外部常驻包装器”，用来给 AI agent 使用 r2 的交互式命令状态。
> 本仓库已废弃该方案，改为在 radare2 源码内实现。本文档只沉淀 r3 中经过实测的
> 关键经验，供后续 C 实现时参考。完整原始文档见 `legacy/r3/docs/`。

## 1. r3 是什么

- CLI 薄客户端 → Unix socket → 常驻 daemon → 抱着 `r2 -q0 -` 管道进程。
- 解决 AI agent 每次新开 bash 时 r2 状态丢失的问题。
- 多会话：每个目标文件一个独立 r2 会话，e 配置与分析状态按文件常驻。

## 2. r2 管道协议（实测结论）

- 必须用 `r2 -q0 -`，不能用裸 `r2 -q0`（会报 missing file）。
- r2 启动后先在 stdout 发一个 **NUL `\x00`** 表示就绪。
- 协议：向 stdin 写 `命令\n`，从 stdout 读到 NUL 即该命令输出结束。
- r2 会在 **stderr** 输出鼠标禁用 ANSI 序列，无法用配置关闭；因此 stdout 是干净通道，
  stderr 要单独进日志。
- `scr.pager=cat` 是关键：空字符串在管道模式下不生效，长输出会挂死等待 stdin。
- `o 新文件` 不会关旧文件、不会清旧分析；跨文件必须重建进程或者使用独立会话。
- `Ps`/`Po` 是工程保存/恢复，可用于缓存秒开；`Po` 有 deprecation warning 走 stderr。
- JSON 输出要显式声明“不截断”，不要用首字符 `{`/`[` 启发式判断。

## 3. 可靠性与自愈设计

- **懒启动**：连不上 socket 自动拉起 daemon。
- **看门狗**：单条命令超时（默认 900s）杀 r2 并按状态/缓存恢复。
- **黑名单**：拒绝 `V`/`Vv`/`Vi`/`ve` 等 visual 交互命令，防管道挂死。
- **并发**：daemon 单线程串行处理，避免竞争。
- **退出码语义**：连接故障、黑名单、超时、截断、无会话、目标不存在/歧义分别用不同码。
- **沙箱降级**：缓存目录不可写时自动降级到纯内存模式。

## 4. 缓存与会话经验

- 缓存键 = 文件内容 SHA-256 + realpath 维度 + r2 版本，避免跨版本/跨路径污染。
- 工程缓存旁写 meta.json 做归属校验，meta 不符即视为未命中。
- 同内容不同路径不共享缓存。
- e 配置按文件持久化，r2 新建/复活后重放。
- 会话 LRU 上限，超限关最久未用的非活跃会话。

## 5. 动态调试边界（r3 v2.x）

- 只做“拉起式调试”：`r2 -d target`，不做 attach（yama 限制）。
- 目标 stdio 经 `dbg.profile` 静音到 `/dev/null`，避免污染命令分帧。
- `--stdin` 只能拉起时快照注入，运行中追加无效。
- r2 不会自动清理 debuggee，需要 killpg 全组清理。
- 调试会话不落工程缓存，现场重分析。

## 6. 对新的 C 实现的建议

1. 复用“stdin/stdout + NUL 分帧”思路，但最好在 r2 内部实现 socket server，
   避免外部包装器。
2. 保留“多会话/每文件一个 RCore”的模型，天然隔离分析状态。
3. 把 r3 的看门狗、黑名单、超时自愈、状态恢复作为 r2 daemon 模式的配置或内建能力。
4. 输出截断/JSON 完整性要由 r2 输出层或 daemon 协议层明确保证。
5. 不要用 `o 新文件` 切文件；要设计干净的 close/reopen 或独立 session。
6. 调试功能先做拉起式，attach/ESIL/远程/内核调试保持边界。
